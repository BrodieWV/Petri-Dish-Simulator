# Product and Engineering Principles

1. The dish must always be doing something readable.
2. Real relationships matter more than exact laboratory numbers.
3. Players learn through consequences rather than long explanations.
4. Failure is diagnostic and must reveal useful information.
5. One authoritative simulation drives visuals, UI, saving, replay, and analytics.
6. Deterministic seeds support debugging, challenges, and sharing.
7. Content is data; new organisms should not require new generic systems.
8. Complexity must produce a distinct decision or visible outcome.
9. The game must not provide unsafe pathogen-cultivation procedures.
10. Build the child-friendly version before advanced scientific modes.
